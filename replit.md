# Fincai - AI Trading Assistant Platform

## Overview
Fincai is an AI-powered day trading assistant with a ChatGPT-style conversational interface. It enables users to analyze stocks, execute trades, and receive market analysis through an intuitive AI. The platform supports a demo mode for anonymous users and live trading for authenticated users, aiming to leverage advanced AI for retail trading while ensuring compliance and a superior user experience. Key features include a live SPY price chart and an intelligent AI assistant for portfolio management via natural language. The AI assistant persona is "Lead Quantitative CFO & AI Architect for Fincai.ai," focusing on analytical, precise, and executive-level communication, with strategic KPI awareness.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend
The frontend is built with React, TypeScript, Vite, and Wouter, utilizing Shadcn/ui (Radix UI, New York style) and Tailwind CSS for styling. It adheres to Material Design principles with a "Lux Black & Gold" theme, featuring dark mode, TanStack Query for server state, React Hook Form with Zod for validation, and Recharts for data visualization. Mobile UX is optimized with a Robinhood-inspired design. User authentication is JWT-based, ensuring protected routes and user-scoped data. Glassmorphism is a key design element, particularly in navigation and trade confirmation dialogs.

### Backend
The backend uses Express.js and TypeScript on Node.js 22, providing RESTful API endpoints and structured error handling. It includes `MarketDataService` for real-time Alpaca market data (with Alpha Vantage as a quote fallback) and dual-layer caching, `GreeksCalculator` (Black-Scholes model), and `StrategyAnalyzer` for payoff/risk metrics. The AI chat system integrates with Claude AI, supporting ReAct reasoning and SSE-based token streaming, with performance enhanced by conversation history trimming and semantic query caching.

### Data Storage
A PostgreSQL database with Drizzle ORM, hosted on Supabase, is used for type-safe queries. The schema includes tables for `strategies`, `options_legs`, `watchlist`, `knowledge_base`, `trades`, `psychology_entries`, option positions, AI caches/recommendations, conversations, and user/session data, ensuring user-scoped and isolated data. The legacy in-app broker tables (broker connections, orders, brokerage accounts, KYC documents, ACH relationships) were removed in the MVP strip; all trading now flows through the Robinhood Agentic Terminal.

### AI Multi-Agent Trading System
Fincai integrates an advanced AI Multi-Agent Trading System utilizing specialized Claude AI agents for technical, sentiment, and fundamental analysis. Features include Bull/Bear Debate and Market Regime Detection, surfaced through the AI chat. Chat interactions employ the ReAct reasoning format. The UI offers a welcome screen with suggested prompts, quick watchlist buttons, an improved chat workspace, and glassmorphic slide-out navigation, operating solely with real-time market data. A "Trade/Plan Mode" toggle allows users to control AI trade execution. A glassmorphic trade confirmation dialog previews portfolio impact. The AI assistant operates under a "Silent Compiler" methodology, ensuring precise, predictable, and compliant behavior through strict syntax, low temperature profiles, structured outputs, and negative constraints (e.g., no execution without user confirmation, no personalized financial advice). Claude API function calling enables real-time trading operations. The system incorporates an "Intent-First Message Router" to classify user messages (e.g., GREETING, STOCK_QUERY, TRADING_COMMAND) before processing, using a symbol blacklist to prevent false positive ticker matches. It includes conversational memory, welcome flows, and error recovery with graceful fallbacks.

### Bring-Your-Own Analysis Provider
The multi-agent analysis system (technical/sentiment/fundamental agents + bull/bear debate) is provider-routable per session: it defaults to the built-in Claude but can run on a user's own connected OpenAI or Google Gemini key. Tool-calling chat intentionally stays on Claude — only analysis is routable. Selection is stored in `aiAnalysisPreferences` (keyed by the server-issued session id; "claude" is represented by the absence of a row, so anonymous sessions work with no setup) and is governed by a curated model allowlist + defaults in `shared/schema.ts` (`PROVIDER_MODELS`). `server/llm-completions.ts` holds dependency-free OpenAI/Gemini REST completers (plain `fetch`, timeout, one transient retry, JSON output mode, sanitized errors that never include the key) plus `resolveAnalysisLlm(sessionId)`. To avoid an import cycle (`anthropic.ts` → `llm-completions.ts` → `ai-provider-store.ts`), the Claude completer lives in `anthropic.ts`, which also implements a **latched fallback**: if a selected bring-your-own provider fails at call time (revoked key, quota, outage), the first failure transparently switches the whole run to Claude and reports `analysisProvider.fallbackUsed`. The `/ai-providers` page surfaces an "Analysis model" selector and a "Try it" panel that runs `POST /api/ai/analyze` (CSRF + rate-limited) and renders the consensus, the three agents, the bull/bear debate, and an "Analyzed by &lt;label&gt;" provenance line. Selecting a provider requires its key already connected; disconnecting it reverts the session to Claude.

### Trading (Robinhood Agentic Terminal)
In-app broker adapters and the order-management system have been removed in the MVP strip; all trading now happens through the Robinhood Agentic Terminal at `/agent`. It connects a live AI agent to Robinhood's Trading MCP server (`https://agent.robinhood.com/mcp/trading`) over MCP Streamable HTTP using OAuth 2.1 (PKCE + dynamic client registration). The OAuth callback URL is derived only from trusted server config (`APP_ORIGIN`/`REPLIT_DOMAINS`), never from request headers, to prevent authorization-code redirection attacks. Connection state is durable across server restarts: the registered OAuth client info and tokens are stored AES-256-GCM-encrypted (via `SESSION_SECRET`) in the `agent_connections` table, keyed by an HttpOnly session cookie, and lazily restored on demand; disconnect — or invalid/unrefreshable tokens — clears the stored record. Demo portfolio data is the fallback whenever no agent is connected. (Alpaca remains in use only as a market-data provider, not for trading.)

### Fincai Autonomous Pricing Engine
A broker-independent, institutional-grade options pricing engine supports multiple asset classes. Key components include Generalized Black-Scholes, Bjerksund-Stensland 2002 approximation for American options, a full Greeks calculator, an IV solver, a yield curve service with Treasury API integration, and a dividend service. The `pricing-engine.ts` orchestrates these services. API routes exist for single option quotes, batch pricing, Greeks, IV, yield curves, dividends, and volatility surfaces. A volatility surface with SVI smoothing is implemented for enhanced analysis, featuring confidence scoring and put-call parity validation. The frontend offers an interactive IV heatmap.

### Option Position Analysis System
A comprehensive Option Position Analysis system includes AI-powered insights. Backend components (`server/position-analytics.ts`, `server/position-tools.ts`, `server/routes/position-routes.ts`) provide moneyness analysis, time decay calculations, Greeks integration, scenario generation, and risk metrics. Six AI function tools enable conversational position analysis, offering summaries, breakeven probability analysis, scenario generation, exit strategy recommendations, rolling options analysis, and position comparison.

### Strategy Templates Library
A curated, read-only catalog of robust trading strategies (`shared/strategy-templates.ts`) derived from an external KalshiBot prediction-market engine and adapted for stocks/options. It is available to all users as plain shared data (no database table, no per-user scoping). Templates include Momentum Breakout Rider (drift entry + trailing/hard/time stops), AI Consensus Convergence (multi-agent debate + trend convergence gating), Fair-Value Edge (pricing-engine fair value vs. market, fractional Kelly sizing), and Mean-Reversion Fade. The catalog also includes a set of institutional quant playbooks adapted from trading-desk methodologies: Time-Series (CTA) Momentum, Cross-Sectional Factor Momentum, Statistical-Arbitrage Mean-Reversion, Volatility Risk Premium (iron condor; runs paper given the short-vol/long-only V1 constraint), and Risk-Parity Core. Long-biased templates can be armed live by the Autonomous Strategy Runner; short/volatility ones are paper-only in V1 and labeled as such. The `/strategy-templates` page presents each with provenance, risk badges, and entry/exit/sizing rules; "Use This Template" deep-links to the Strategy Builder via `/builder?template=<id>`, which prefills the form (type, risk profile, stop/target/time/trailing, symbol) — finally activating the `strategies` table's previously-unused risk-management fields.

### Autonomous Strategy Runner
The strategy templates are not just static catalog entries — a server-side background engine (`server/strategy-runner.ts`) makes them ACTUALLY RUN. It watches live quotes on a single non-overlapping interval and auto-applies each template's entry trigger, stop-loss, profit-target, trailing-stop, and time-stop, managing real EQUITY trades through the user's connected Robinhood Agentic Trading MCP. The `strategy_runs` table persists each run's state machine (watching → entering → in_position → exiting → closed, plus error/paused), and the engine resumes active runs on boot. The frontend `strategy-runner-panel.tsx` (rendered on `/builder`) lets users arm a template (symbol, shares, editable rules), toggle paper vs. live, stop individual runs, or hit a kill switch; the active-runs list polls every ~5s.

Safety model: **paper (simulated) is the default; live is explicit per-run opt-in**. Anonymous users are paper-only; live requires a connected Robinhood agent and is **long-only in V1** (short-direction templates run in paper). Position caps (max quantity + max notional, centralized in `server/strategy-run-limits.ts`) are re-checked against the live price at entry, with a market-hours guard for live entries/exits. Entry/exit triggers are computed from quotes only (no real multi-agent/fair-value compute in the loop) and labeled as such in the UI. **Idempotency:** the in-flight status (entering/exiting) is persisted BEFORE the MCP order, and an atomic compare-and-set (`storage.tryTransitionStrategyRun`) guards every transition so the periodic tick and a user's manual Stop/kill cannot double-act on a run; any run found stuck mid-order on restart — or any failed live order — is set to `paused` for manual review and never auto re-placed. The strategy-run POST routes validate CSRF before optional-auth, and the app primes the CSRF cookie on mount so anonymous paper runs don't 403.

Deployment caveat: the engine is an in-process interval loop. On an **autoscale** deployment that scales to zero the loop stops when the instance is torn down (runs resume on next boot, but paused/mid-order ones stay paused); for always-on autonomous trading use a Reserved VM.

### Market Data Service Caching
The `MarketDataService` implements a multi-tier caching strategy with adaptive TTL and stale-while-revalidate patterns to optimize API usage and reduce rate-limit pressure. This includes L1 Hot Cache, L2 Main Cache, and a Stale Data Window, with base cache durations for quotes, intraday, and options data. Adaptive caching extends cache TTL when 429 rate-limit errors are detected, and a stale-while-revalidate pattern ensures responsiveness by serving slightly aged data while background refreshes occur. Cache and provider refresh cycles are set to 1 minute. A manual refresh button is present in the chart UI.

### Market Data Audit Log
A persistent audit log (`market_data_audit_log` table) tracks every market data API access event. The `MarketDataService.emitAuditEvent()` fires asynchronously (non-blocking) at each provider decision point: cache hits, fresh provider fetches (Alpaca, Alpha Vantage, Demo), and provider failures. Each entry records: symbol, endpoint, provider, cacheResult (hit/miss/stale), HTTP status code, latency in ms, error message, and a metadata JSONB field (interval, data points returned, etc.). A `computeEventType()` helper derives an `eventType` field ("cache_hit" | "fresh" | "rate_limit" | "error") from each event automatically. Coverage spans all endpoints: quote, intraday, historical, options, and movers. The `GET /api/admin/market-audit` endpoint is auth-protected (requires login) and supports filters for symbol, provider, eventType, date range, limit, and offset.

### Psychology Tracker
The Psychology Tracker (`/psychology`) persists a trader's emotional state and daily mistakes to the database (`psychology_entries` table: userId, entryType `emotion`|`mistakes`, emotion, notes, mistakes[]). It is served by `GET`/`POST /api/psychology-entries` using the same `optionalAuthForFeatures` + shared demo-user pattern as `/api/strategies`, so anonymous users get full functionality and entries survive page refreshes. The page uses TanStack Query mutations with cache invalidation and renders emotions with lucide icons (no emojis).

### Market Analysis Tools
The Market Analysis page (`/market-analysis`) operates on real data. It shows a live Market Overview (key indices SPY/QQQ/WMT/VIX from `GET /api/market/summary` and gainers/losers/most-active from `GET /api/market/movers`, with loading skeletons and graceful "Unavailable"/error states), plus an "analyze a symbol" flow that pulls real Alpaca OHLC from `GET /api/market/historical/:symbol` and auto-runs the four technical calculators (pivot points, fibonacci, ATR, bollinger bands) via the existing `POST /api/market-analysis/*` endpoints. Manual JSON entry remains as an advanced fallback.

### Promotional Tour Page
The `/promo` page is a cinematic, auto-advancing "promotional video" built from animated slides (`framer-motion`) rather than a real video file. It renders as a full-screen overlay (`fixed inset-0`) driven by a normal route, walking through Fincai's core features — conversational AI, multi-agent analysis, the autonomous strategy runner, the Robinhood agentic terminal, the options pricing engine, real market data, and the psychology tracker — in the Lux Black & Gold glass theme. It auto-plays with a segmented progress bar and full playback controls (play/pause, prev/next, restart, clickable segments, keyboard arrows/space/Esc), pauses on tab-hide, and respects `prefers-reduced-motion` (no autoplay/motion). It is SEO-configured in `shared/seo-config.ts` and listed in the sitemap, and is linked from the sidebar ("Watch Demo") and the landing hero ("Watch the tour"). The closing slide has CTAs into the app (`/` and `/chat`) plus the standard compliance and Robinhood disclaimers.

-   **Market Data (supplemental)**: Alpha Vantage (quote fallback)
